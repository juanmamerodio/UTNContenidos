01 // System Architecture

El Paradigma JAMstack

UTNContenidos abandona la idea de un servidor centralizado. La lógica computacional pesada (IA, parseo de RAG) se mueve al Edge (Vercel), la interfaz de usuario se despacha estáticamente, y los servicios de Google actúan puramente como microservicios de I/O de documentos y almacenamiento temporal.

Serverless Edge Functions

Las funciones en Vercel resuelven el cuello de botella de los 6 minutos de Google Apps Script. El Frontend se comunica con /api/gemini, procesa la LLM, y devuelve JSON estructurado al cliente en menos de 4 segundos.

03 // Post-Mortem Log

Bitácora de Imprevistos y Pivotes

Documentación de fallas críticas en entornos de producción y las soluciones de ingeniería aplicadas para remediarlas.

ERR-001: Limitación Computacional GAS

FATAL EXCEPTION: Executed timeout limit exceeded (6.0 min)

Problema: En la Fase 1, Google Apps Script manejaba la petición a Gemini LLM de forma sincrónica. En temas complejos, la inferencia de la IA + la creación del PPT en Drive superaba el límite inquebrantable de 6 minutos de Google, rompiendo la aplicación.

Resolución: Arquitectura JAMstack. Se delegó el *fetching* asíncrono de la IA al cliente web interactuando con un Edge Function en Vercel. GAS ahora solo ejecuta operaciones locales instantáneas (lectura de celdas y creación rápida de slides).

ERR-002: Inyección Markdown LLM

SyntaxError: Unexpected token '`', "```json..." is not valid JSON

Problema: Al solicitar respuestas estructuradas, el modelo de IA envolvía el código en etiquetas markdown. El bloque try/catch colapsaba al intentar parsear el objeto directamente al frontend.

Resolución: Tipado estricto en API. Se modificó el payload de la petición HTTP agregando la directiva de configuración de generación nativa: generationConfig: { responseMimeType: "application/json" }, obligando al modelo a omitir tokens de formato de texto.

BUG-003: Interfaz Fantasma (Fallo Relacional)

UI RENDER: Materia object mapped with topics.length === 0

Problema: El frontend dibujaba la tarjeta de la materia, pero no los temas ni el botón "Preparar Clase". El cruce de tablas en Google Sheets requería coincidencia tricondicional estricta (Legajo + ID_Materia + Tema). Al faltar el mapeo en la DB, el array se purgada silenciosamente.

Resolución: Rediseño del script Backend para proveer un atributo warning en el JSON y rediseño de la UI para mostrar "Empty States" claros avisando al docente de la falta de configuración de datos maestros.

04 // Data Dictionary

Estructura de Base de Datos

Esquema físico actual de las entidades implementadas en la solución temporal de almacenamiento (Google Sheets DB).

Tabla: Docentes

Columna Tipo de Dato Clave Descripción
A - Legajo Integer PK Identificador único del profesor en UTN.
B - DNI String UNIQUE Credencial de acceso sin formato.
C - Nombre String - Nombre completo a mostrar en UI.
E - ID_Materias String (CSV) FK_Array Lista separada por comas de IDs referenciando a tabla Materias.

Tabla: Historial_Presentaciones (Transaccional)

Columna Tipo de Dato Clave Descripción
A - ID_Historial UUID PK Generado mediante Utilities.getUuid() en GAS.
B - Legajo_Docente Integer FK Relación al propietario de la diapositiva.
E - URL_Slides URL - Enlace directo a Google Drive (devuelto por SlidesApp).
F - Fecha_Creacion DateTime - Timestamp para ordenado (DESC) en el dashboard de historial.
